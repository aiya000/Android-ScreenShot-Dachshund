# ブラウザのページは、行がピクセル単位では一致しない

## おこったこと

BOOTH の検索結果（商品カードの格子）を撮ると、ページ同士の重なりが見つからず、結合がずれた。
設定アプリでは問題なかった。

## 原因

二つ重なっていた。

- ブラウザは CSS px の倍率で端数ピクセルぶんスクロールし、描画を再サンプリングする。同じ内容でも
  行のピクセルが毎回わずかに違い、「行ハッシュが完全一致」の判定がほとんど通らない。
  無地の背景行しか一致せず、画像の多いページほど候補が決まらなかった
- 商品画像の上で縦にスワイプすると、そのカードの画像が別の写真に切り替わる（カルーセル）。
  自動スクロールの指が画像に当たると、次のページでその領域がまるごと変わる

計測（scratchpad の `analyze-overlap.py`、完全一致で数えた場合）: 正しい距離でも一致率は 70%、
ページ末尾の「ほぼ同じで 26px ずれた」ページでは 2〜4 割で、距離 0 が最良になっていた。

## したこと

- 行の比較を `RowSketch`（行を 16 区間の平均明度にした指紋）の「近さ」に変えた
  （`alike` = 平均差 10/255 以内）。ハッシュは「同じ画面の撮り直しかどうか」の判定にだけ残した
- `Joiner.findOverlap`: 帯は 75% の行が近ければ候補を出す。候補の距離は、重なり部分の
  **模様のある行**（`textured`、指紋の幅が 16 以上）のうち近い行の数で採点し、
  30% かつ 8 行以上を満たした最良のものを採る。無地の行はどの距離でも近いので数えない
- `FixedEdges` も指紋の近さで数える

## 次に気をつけること

- テスト用の合成ページ（`TestPages`）の行は、ちゃんと混ぜた擬似乱数で作ること。
  単純な乗算だと隣の id が「ずらした同じ列」になって、偶然「近い」行ができ、テストが揺れる
- 実ページで再現するときは、エミュレータの Chrome で撮って `run-as` でページを取り出し、
  Python（Pillow）で距離ごとの一致率を数えると早い

- `app/src/main/kotlin/.../image/RowSketch.kt`
- `app/src/main/kotlin/.../join/Joiner.kt`, `FixedEdges.kt`
